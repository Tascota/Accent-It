# Accent It

Accent It 是一个自用的 Windows 桌面工具，用于给 Unicode 字母添加组合附加符号。默认优先输出预组合字符，也可以切换为完全分解形式。

技术栈：C#、.NET 10、WPF。

## 当前进度

阶段 1 的最小可用版本已经完成：

- 输入单个基础字母。
- 按配置中的“上方 / 下方 / 叠加”等位置分组显示组合符号。
- 用鼠标点击，或用 Tab 聚焦后按空格，选择或取消符号。
- 选择后立即更新预览；已选符号可以单独移除、撤销上一个或清空。
- 默认优先输出预组合字符（NFC），并可在预览标题旁切换为 NFD 完全分解。
- 显示组合方式、Unicode 码点、NFC、NFD 诊断信息。
- 复制结果到剪贴板。
- 从 JSONC 文件读取符号目录、位置分组和组合策略；无效配置会报告问题，不会让程序崩溃。
- 第一次运行时，从程序自带的默认目录生成一份可编辑的用户目录；之后不会覆盖用户修改。

阶段 2 的第 1 步（全局快捷键）已经完成：

- 启动时从 `Data/settings.jsonc` 读取全局快捷键，默认 `Ctrl+Alt+Space`。
- 使用 Windows 的 `RegisterHotKey` 注册系统级快捷键，Accent It 不需要保持在前台。
- 快捷键被其他程序占用时，界面显示未注册原因，程序仍可正常使用。
- 第一次运行自动创建设置文件；设置文件有误时回退到默认快捷键，并在“诊断详情”中报告问题，不覆盖用户文件。

阶段 2 的第 2 步（紧凑输入窗口）已经完成：

- 在其他应用前台按全局快捷键，会打开一个约 520×640 DIP 的快速输入窗口；它置顶、不显示在任务栏。
- 紧凑窗口复用同一份符号目录和组合逻辑，支持基础字母、按位置分组的符号、按选择顺序排列的已选符号、实时预览和 NFC/NFD 切换。
- Esc 关闭，Backspace 在未编辑基础字母框时删除最近添加的符号。
- 重复按快捷键只激活已有的紧凑窗口，不会重建窗口，也不会清空当前输入。
- 符号目录加载失败时，窗口显示错误并禁用组合和插入。

阶段 2 的第 3 步（目标定位与跨应用插入）已经完成：

- 按快捷键时捕获当前前台应用、进程/线程、输入焦点和可用的光标位置，再打开紧凑窗口。
- 优先把窗口放到 Win32 系统光标附近；没有系统光标时尝试 UI Automation 文本选区或输入框边界，再退回鼠标位置或目标显示器工作区中央。
- 窗口位置按物理像素计算，使用 `SetWindowPos` 放置，避免 150% 缩放下的 DIP 换算偏移。
- Enter 或“插入”会：验证目标仍存在 → 备份剪贴板 → 写入结果 → 把目标切回前台并恢复输入焦点 → 等待修饰键松开 → 核对剪贴板 → 发送 Ctrl+V。
- 插入后紧凑窗口保持打开并移到工作区角落，不会用自动关闭假装粘贴一定成功；状态文字明确说明“已发送 Ctrl+V，但无法确认目标是否显示文本”。
- 关闭紧凑窗口时，如果剪贴板仍是本次写入的结果，就恢复原剪贴板；如果用户点过“复制结果”或期间复制了别的内容，则不覆盖。
- 目标关闭、目标最小化、焦点无法恢复、剪贴板和发送失败时，都会停止自动插入，保留结果供手动复制。
- UI Automation 报告为密码框时不读取内容，禁用“插入”，Enter 只复制结果。

实际测试过的应用和结果见下方“跨应用插入测试记录”。没有测试到的应用不能据此认为兼容。

## 环境要求

- Windows
- .NET 10 SDK
- .NET 10 Desktop Runtime（运行已构建的应用时）

## 构建、测试与运行

在本仓库根目录执行：

```bash
dotnet build AccentIt.slnx
dotnet test AccentIt.slnx
dotnet run --project src/AccentIt
```

项目使用 .NET 10 默认的 `.slnx` 解决方案格式；使用 `dotnet` CLI 构建即可，不依赖 Visual Studio。

当前共有 65 个自动化测试，覆盖配置解析与校验、用户配置创建与回退、快捷键解析与设置文件创建/回退、NFC/NFD 组合、部分预组合、例外规则、Unicode 非 BMP 字符和紧凑窗口定位的纯逻辑。

## 使用方式

1. 启动程序。第一次启动会在程序目录的 `Data` 文件夹中生成 `accents.jsonc`。
2. 在“基础字母”输入框中输入一个 Unicode 字母。
3. 点击任意组合符号按钮；也可以按 Tab 移动焦点，再按空格选择或取消。
4. 右侧“预览”会立即显示结果；标题旁的“输出 NFC / NFD”可以切换规范化形式。“已选符号”按选择顺序排列。
5. 点击已选符号上的 `×`、使用“撤销上一个”或“清空”来调整选择。
6. 点击“复制结果”把预览文本写入剪贴板。
7. 展开“诊断详情”可以查看配置来源、设置文件、原始序列、NFC、NFD、配置问题和设置问题。
8. 程序运行期间，在 Accent It 以外的应用前台按全局快捷键（默认 `Ctrl+Alt+Space`），会捕获当前目标并打开紧凑输入窗口；在紧凑窗口中按 Enter 会尝试插入结果。

界面上的 NFC/NFD 切换只影响当前运行；重启后的默认值由 `accents.jsonc` 中的 `composition.mode` 决定，切换不会写回配置文件。

### 快速输入窗口

1. 先在目标应用里点一下准备输入的位置，确认光标或输入框有焦点。
2. 按全局快捷键（默认 `Ctrl+Alt+Space`）。完整编辑器不需要在前台，但程序必须仍在运行。
3. 窗口顶部的“目标：…”显示捕获到的应用和定位方式，例如“已定位系统光标”或“已定位文本选区”。
4. 输入基础字母并选择组合符号；预览会实时更新。NFC/NFD 切换只影响紧凑窗口当前这次输入，不会改动完整编辑器的选择。
5. 按 Enter 或点击“插入（Enter）”。插入成功后，窗口保持打开并移到角落，以便检查目标文本。
6. 插入后按 Enter 或 Esc 关闭窗口；如果窗口没能自动回到前台，按钮会变成“完成”/“关闭”，请直接点击，或再按一次全局快捷键把窗口带回前台。
7. 如果目标是密码框、Accent It 自己，或者没有捕获到外部目标，Enter 只复制结果，不会向目标发送粘贴。
8. 按 Backspace 删除最近添加的符号；当焦点在基础字母输入框内时，Backspace 保持正常的文本编辑行为。
9. 插入前按 Esc 或“取消”关闭窗口：不修改目标文本，也不读写剪贴板，并尽量把焦点还给原目标。
10. 插入后关闭窗口时才恢复原剪贴板；如果之前点过“复制结果”，则保留结果，不恢复旧内容。
11. 再次按全局快捷键时，如果紧凑窗口已经打开，只会把它带到前台，不会重置当前输入。
12. 每次重新打开紧凑窗口，都会从新的组合状态开始；完整编辑器里的选择不受影响。

窗口位置依次尝试：系统光标下方 → UI Automation 文本选区/输入框 → 鼠标位置 → 目标显示器工作区中央；空间不足时会翻到光标上方或钳制在工作区内。本机只在单显示器 150% 缩放下做过位置验证，混合 DPI 多显示器尚未验证。

> **注意：** 紧凑窗口是置顶窗口；关闭它不会退出 Accent It，也不会把已经插入的文本撤销。自动插入只表示已经发送 Ctrl+V，不能保证每个应用都接受粘贴。

## 可编辑的配置文件

符号目录和全局快捷键都不是写死在 C# 里的。界面使用的数据来自程序目录旁的 JSONC 文件：

| 文件 | 作用 | 是否会被程序覆盖 |
| --- | --- | --- |
| `Data/accents.default.jsonc` | 程序自带的默认符号目录（种子） | 构建时可能被源文件更新 |
| `Data/accents.jsonc` | 用户实际编辑的符号目录 | 已存在时不会被覆盖 |
| `Data/settings.jsonc` | 用户编辑的全局快捷键设置 | 首次运行创建，已存在时不会被覆盖 |

`Data` 是相对于可执行文件所在目录的。开发时它们位于：

```text
src/AccentIt/bin/Debug/net10.0-windows/Data/accents.default.jsonc
src/AccentIt/bin/Debug/net10.0-windows/Data/accents.jsonc
src/AccentIt/bin/Debug/net10.0-windows/Data/settings.jsonc
```

程序启动时，如果 `accents.jsonc` 不存在，会把它从 `accents.default.jsonc` 复制出来。之后只读取 `accents.jsonc`，不会用默认文件覆盖它。

源码中的默认目录位于：

```text
src/AccentIt/Data/accents.default.jsonc
```

修改建议：

1. 启动一次程序，让 `Data/accents.jsonc` 自动生成。
2. 编辑 `Data/accents.jsonc`。
3. 重启程序后生效；当前没有文件热重载。
4. 如果 `accents.jsonc` 有错误，程序会把问题显示在“诊断详情”中，并回退到默认目录，不会直接崩溃。

> **重要：** 用户配置在构建输出目录里，执行 `dotnet clean`、删除 `bin` 或清理发布目录会把它一起删掉。请定期备份 `Data/accents.jsonc`。日常使用时，建议发布到一个独立文件夹，而不是长期依赖 `bin/Debug`。

## JSONC 配置格式

配置文件使用 UTF-8 编码，接受 `//` 注释和尾随逗号。格式错误的 JSON 会被拒绝。

顶层结构：

```jsonc
{
  "schemaVersion": 1,

  "positions": [
    { "id": "above", "displayName": "上方" },
    { "id": "below", "displayName": "下方" },
    { "id": "overlay", "displayName": "叠加" }
  ],

  "marks": [
    {
      "id": "acute",
      "codePoint": "U+0301",
      "name": "锐音符",
      "position": "above",
      "description": "可选说明"
    }
  ],

  "composition": {
    "mode": "nfc",
    "rules": []
  }
}
```

字段说明：

- `schemaVersion`：当前只支持 `1`。
- `positions`：位置分组，数组顺序就是界面显示顺序。`id` 只能包含 ASCII 字母、数字、`-`、`_`、`.`，且不能重复。
- `marks`：组合附加符号。`codePoint` 推荐使用 `U+XXXX` 形式；符号必须是 Unicode 组合附加符号（nonspacing、spacing combining 或 enclosing mark）。`position` 必须引用已定义的位置。`id` 和码点都不能重复。
- `composition.mode`：
  - `"nfc"`：默认。输出 NFC 规范化结果。若无法完整预组合，可能得到“部分预组合”的序列。例如 `a` + 锐音符 + 下点符可能得到 `ạ` 加上一个锐音符。
  - `"nfd"`：完全分解输出，永远不使用预组合字符，只输出基础字母与按 NFD 规范排列的组合符号。例如 `a` + 锐音符 + 下点符得到 `U+0061 U+0323 U+0301`。此模式不应用例外规则。
- `composition.rules`：显式例外映射，只在 NFC 模式下生效。某些字符（例如 `ø`、`ł`、`đ`）没有 NFC 规范分解，不能仅靠基础字母加组合符号自动得到，需要在这里写规则。

一条例外规则：

```jsonc
{
  "base": "o",
  "marks": ["overlay-long-slash"],
  "resultCodePoint": "U+00F8",
  "note": "o + 长斜线 → ø；这是显式映射"
}
```

规则行为：

- `base` 必须是单个 Unicode 字母。
- `marks` 必须引用 `marks` 中已定义的符号 id，不能重复。
- `resultCodePoint` 必须是单个 Unicode 字母。
- 规则匹配只看“基础字母和符号 id 的集合”，与符号选择顺序无关。
- 在 NFC 模式下，只要匹配到规则，规则优先于自动组合。
- NFD 模式完全分解，不应用例外规则。
- 同一基础字母和同一组符号 id 不能定义两条重复规则。

## 全局快捷键设置

设置文件 `Data/settings.jsonc` 在第一次启动时自动创建，默认内容：

```jsonc
{
  "schemaVersion": 1,

  // 全局快捷键：至少一个修饰键 + 一个主键。
  // 支持 Ctrl / Alt / Shift / Win，以及字母、数字、Space、F1-F24（F12 除外）。
  // 修改后重启 Accent It 生效。
  "hotkey": "Ctrl+Alt+Space"
}
```

- `schemaVersion`：当前只支持 `1`。
- `hotkey`：至少包含一个修饰键（Ctrl、Alt、Shift、Win），加一个主键。
- 支持字母 A–Z、数字 0–9、Space、F1–F24。F12 保留给系统调试，配置时会被拒绝。
- 修饰键和主键不区分大小写，例如 `ctrl + shift + a` 会规范化为 `Ctrl+Shift+A`。
- 建议避开常用软件占用的组合，例如 QQ 的 `Ctrl+Alt+A`、微信的 `Alt+A`。
- 修改后重启程序生效；当前不监听设置文件变化。
- 如果组合已被其他程序占用，程序启动时注册失败，主界面会显示冲突提示；其他功能仍可使用，改好设置后重启即可。程序不会自动重新注册。
- 如果设置文件 JSON 格式错误、`schemaVersion` 不支持或快捷键无效，程序使用默认 `Ctrl+Alt+Space`，并在“诊断详情 → 设置问题”中说明原因，不会覆盖原文件。
- 主界面的“打开设置文件”按钮可以直接打开这个文件。
- Win 组合键能否注册取决于系统和已运行程序，可能被系统保留。
- 关闭完整编辑器会退出程序并注销快捷键。当前阶段没有托盘、开机启动或安装包。

## 已知限制

- 预组合依赖 Unicode NFC 的规范组合规则。像 `ø`、`ł`、`đ` 这类没有规范分解的字母，不能仅靠“基础字母 + 组合符号”自动得到；需要显式规则。
- 多个组合附加符号的显示效果取决于字体；码点正确不代表所有程序中外观一致。
- Windows 剪贴板与其他应用的文本处理行为可能改变最终的码点表现。
- 全局快捷键只在启动时注册一次。启动时若被占用，即使占用的程序之后退出，Accent It 也不会自动重新注册，需要重启。
- 自动插入目前只在 Windows 11 记事本和隔离的 Edge 临时页面中实测通过。VS Code、Chrome、Windows Terminal、管理员权限目标等没有实测，不能视为兼容。
- 如果目标应用以管理员权限运行，而 Accent It 不是管理员，Windows 的 UIPI 会阻止 `SendInput`，插入会失败；界面会提示可手动复制。
- 自动插入依赖目标应用接受 Ctrl+V。某些程序可能拒绝粘贴、使用不同的快捷键，或者把粘贴处理成富文本；Accent It 无法确认目标文本是否真的改变，只报告“已发送 Ctrl+V”。
- 密码框的识别依赖 UI Automation 或经典 Win32 Edit 样式。无法识别为密码框的自绘控件仍可能被当成普通目标；不要在敏感输入框中自动插入。
- 粘贴前会核对顶层窗口、进程/线程和目标焦点是否还能恢复；但无法在所有应用里证明用户意图中的具体光标位置没有变化。焦点无法恢复时会停止自动插入。
- 光标定位依赖目标应用暴露系统光标或 UI Automation；不暴露时回退到鼠标位置或显示器工作区中央。混合 DPI 多显示器、屏幕旋转和特殊窗口布局没有验证。
- 剪贴板备份只覆盖常见格式（UnicodeText、Text、Html、Rtf、Csv、FileDrop、Bitmap），延迟渲染或特殊格式不能保证完整恢复。剪贴板历史可能记录临时插入结果。
- 插入后 Windows 可能拒绝把紧凑窗口自动切回前台；此时窗口仍置顶，可点击按钮关闭，或再按一次全局快捷键把它带回前台。

# Accent It

Accent It 是一个 Windows 桌面工具，用于从基础字母组合出 Unicode 字符：既可以添加组合附加符号，也可以用“倒转”“加钩”“合字”等抽象操作得到特殊字母，并输出 NFC 或 NFD 结果。

**声明：**本项目完全基于 vibe coding，仅以满足本人个人使用需求为目标。请务必不要用于关键生产环境。

它提供两种输入方式：

- **完整编辑器**：查看符号分组、调整选择、核对 NFC/NFD 结果并复制。
- **紧凑输入窗口**：通过全局快捷键在其他应用前打开，把结果尝试粘贴到当前光标位置。

## 主要功能

- 按 Unicode 组合规则生成 NFC 或 NFD 结果，并显示码点和诊断信息。
- 通过字母变形路径组成特殊字符，例如 `M + 倒转 → Ɯ`、`i + j + 合字 → ĳ`；没有匹配路径时明确提示，不会自动猜测结果。
- 没有通用变形关系的字母（如 `ð`、`þ`）可以从可搜索的“其他字符”列表直接选择。
- 符号目录、位置分组、例外规则、字母变形路径、其他字符和全局快捷键都可以通过 JSONC 文件修改。
- 紧凑窗口中的符号围绕预览字母四边排列，支持变形、合字和连续插入。
- 主窗口和紧凑窗口可以共享当前输入，并支持浅色/深夜模式。
- 关闭主窗口后程序留在系统托盘，全局快捷键继续可用。

## 隐私

Accent It 在本地运行，当前版本没有联网或遥测功能。为了插入文本，程序会读取剪贴板以进行备份，并捕获目标窗口和输入焦点信息；这些内容不会被 Accent It 上传。被识别为密码框时，不会读取其内容或自动插入。配置和主题只保存在程序目录旁的 `Data` 文件夹。

Windows 剪贴板历史或其他剪贴板工具仍可能记录插入过程中写入的临时内容，详见“注意事项与已知限制”。

## 环境要求

- Windows（已在 Windows 11 上测试；其他 Windows 版本未完整验证）
- 从源码运行需要 .NET 10 SDK（版本以 [global.json](global.json) 为准）
- 运行已构建程序需要 .NET 10 Desktop Runtime

当前没有安装包、开机启动或自动更新。

## 运行

在仓库根目录执行：

```bash
dotnet run --project src/AccentIt
```

首次启动时，程序会在可执行文件旁的 `Data` 文件夹创建快捷键设置；切换过的主题保存在同一目录的 `theme.json`。符号目录随程序提供，不再生成用户副本。构建和测试命令见 [开发记录](docs/DEVELOPMENT.md)。

## 使用方法

### 完整编辑器

1. 启动程序，在“基础字母”输入框中输入一个 Unicode 字母。
2. 在左侧选择组合方式：
   - **组合符号**：点击符号按钮选择或取消；也可以按 Tab 移动焦点，再按空格切换。
   - **字母变形**：点击“倒转”“加钩”等操作，可以选择多个；选择“合字”后，右侧会出现“合字的第二个字母”输入框。匹配成功时显示路径（如 `M + 倒转 → Ɯ（U+019C）`）；没有匹配规则时显示“没有这条组合路径”，并禁用复制。
   - **其他字符**：搜索字母、Unicode 名称、别名或码点，点击结果会把它设为基础字母并清空当前选择。
3. 右侧“预览”会立即显示结果。点击标题旁的“NFC / NFD”切换规范化形式。
4. “已选变形”和“已选符号”区域显示当前选择；可以点击标签上的 `×` 单独移除，或使用“撤销”“清空”。
5. 点击“复制结果”把预览写入剪贴板。
6. 展开“诊断详情”可以查看配置来源、设置文件、原始序列、NFC、NFD 和配置问题。
7. 点击右上角的“紧凑窗口 (F2)”或按 F2 切换到紧凑窗口，当前输入会一起带过去。
8. 点击“深夜模式”切换深色界面；再次点击“日间模式”恢复浅色。

NFC/NFD 切换只影响当前运行。重启后的默认值由 `Data/accents.default.jsonc` 中的 `composition.mode` 决定，界面切换不会写回配置文件。

字母变形路径在 NFC 和 NFD 下都会先生成结果字母；符号例外映射只在 NFC 下生效。例如 `M + 倒转` 在两种模式下都会得到 `Ɯ`，再按所选模式处理附加符号。

### 快速输入窗口

1. 先在目标应用中点一下准备输入的位置，确认光标或输入框有焦点。
2. 按全局快捷键（默认 `Ctrl+Alt+Space`）。完整编辑器可以不在前台，也可以已经隐藏到托盘；程序必须仍在运行。
3. 窗口顶部显示捕获到的目标应用。如果目标是密码框，会注明并且不会自动插入。
4. 输入基础字母，点击围绕在预览四边的符号按钮。符号名称和码点保留在悬停提示中。
5. 需要变形时点击“变形”，在覆盖面板中选择一个或多个操作。选择“合字”后会显示“第二字母”输入框；面板底部会显示匹配到的路径（如 `M + 倒转 → Ɯ（U+019C）`）。没有匹配时显示“没有这条组合路径”，并禁用“插入”和“复制结果”。
6. 没有通用变形路径的字符，点击“其他”打开可搜索列表。点击字符后，它会成为基础字母，当前符号、变形和第二字母会被清空。
7. 按 Enter 或点击“插入 (Enter)”。插入成功后窗口保持打开，基础字母和当前选择会被清空，可以继续输入下一个字母。
8. 如果没有看到插入结果，切回目标应用按 `Ctrl+V` 手动粘贴；也可以点击“复制结果”后再粘贴。如果紧凑窗口没有回到前台，再按一次全局快捷键把它带回。
9. 插入前按 Esc 或点击“取消 (Esc)”关闭：不修改目标文本，也不读写剪贴板，并尽量把焦点还给原目标。工具面板打开时，Esc 先关闭面板。
10. 插入后关闭窗口时，只有剪贴板仍是本次写入的结果才恢复原剪贴板；如果点过“复制结果”或期间复制了新内容，则不恢复。
11. 按 Backspace 删除最近输入的内容，顺序是：第二字母 → 最后一个变形 → 最后一个符号。当焦点在输入框内时，Backspace 保持正常的文本编辑行为。
12. 点击“完整编辑器 (F2)”或按 F2 切换到完整编辑器，基础字母、已选符号、变形、第二字母和 NFC/NFD 会一起带过去。从主窗口进入的紧凑窗口关闭后会自动回到主窗口。
13. 如果目标是密码框、Accent It 自己，或者没有捕获到外部目标，Enter 只复制结果，不会发送粘贴。
14. 再次按全局快捷键时，如果紧凑窗口已经打开，只会把它带到前台，不会重置当前输入。由快捷键直接打开时从新的组合状态开始；从主窗口切换过去时保留主窗口的输入。

窗口位置依次尝试：系统光标下方 → UI Automation 文本选区或输入框 → 鼠标位置 → 目标显示器工作区中央。空间不足时会翻到光标上方或限制在工作区内。目前只在单显示器、150% 缩放下验证过位置，混合 DPI 多显示器尚未验证。

> **注意：** 紧凑窗口是置顶窗口。插入成功后清空当前输入，但不会自动关闭，也不会撤销目标应用里已经插入的文本。自动插入只表示已经尝试发送 Ctrl+V，不能保证每个应用都接受粘贴；失败时应使用“复制结果”手动粘贴。

### 托盘与退出

关闭完整编辑器不会退出程序，而是隐藏到系统托盘，全局快捷键继续可用。单击托盘图标，或右键选择“打开 Accent It”，可以重新显示完整编辑器。

需要真正退出时，右键托盘图标选择“退出 Accent It”。如果正在执行插入，退出会被拒绝并提示等待，避免剪贴板停在临时状态。托盘图标创建失败时，程序退回“关闭主窗口即退出”的行为。

Windows 11 通常把新托盘图标放在任务栏的“显示隐藏的图标”区域；是否常驻取决于系统的任务栏/通知区域设置。当前没有开机启动。

### 界面主题

主题按钮位于主窗口右上角和紧凑窗口顶部，不需要快捷键：

- 当前为浅色时，主窗口按钮显示“深夜模式”，紧凑窗口按钮显示“深色”；当前为深色时分别显示“日间模式”和“浅色”。
- 两个窗口共用同一个选择，切换后已打开的窗口立即更新。
- 主题只改变 Accent It 的界面颜色，不修改 Windows 系统主题，也不影响符号目录、NFC/NFD 输出或剪贴板。
- 选择保存在 `Data/theme.json`，不会写入或覆盖 `settings.jsonc`、`accents.default.jsonc`。
- 文件缺失、值未知或 JSON 损坏时使用浅色主题。
- 深夜模式使用冷调蓝黑背景和天蓝强调色，并尽量让 Windows 11 标题栏使用相同背景色；不支持自定义标题栏颜色的环境只保留内容区配色。
- 主题不跟随 Windows 系统主题自动变化。

## 配置文件

符号目录、字母变形路径和全局快捷键都不是写死在代码里的。界面使用的数据来自程序目录旁的 JSONC 文件：

| 文件 | 作用 | 是否会被程序覆盖 |
| --- | --- | --- |
| `Data/accents.default.jsonc` | 符号目录、字母变形路径和其他字符；程序直接读取此文件 | 源码文件较新时，构建会更新输出目录中的副本 |
| `Data/settings.jsonc` | 用户编辑的全局快捷键设置 | 首次运行创建，已存在时不会被覆盖 |
| `Data/theme.json` | 程序记录上次选择的界面主题 | 切换主题时由程序写入，不包含快捷键或符号配置 |

`Data` 相对于可执行文件所在目录。开发运行时默认位于：

```text
src/AccentIt/bin/Debug/net10.0-windows/Data/accents.default.jsonc
src/AccentIt/bin/Debug/net10.0-windows/Data/settings.jsonc
src/AccentIt/bin/Debug/net10.0-windows/Data/theme.json
```

程序直接读取 `Data/accents.default.jsonc`，不再生成或读取 `Data/accents.jsonc`。旧版本留下的 `accents.jsonc` 会保留在原处，但不会参与加载。源码中的默认目录位于 `src/AccentIt/Data/accents.default.jsonc`，构建时复制到输出目录。

修改配置的步骤：

1. 编辑 `src/AccentIt/Data/accents.default.jsonc`，或直接编辑输出目录中的 `Data/accents.default.jsonc`，修改符号、字母路径和其他字符。
2. 编辑 `Data/settings.jsonc` 修改全局快捷键；该文件在首次运行时自动创建。
3. 重启程序后生效；当前没有文件热重载。
4. 符号目录有错误时，程序会在“诊断详情”中列出原因并拒绝加载，没有备用目录；快捷键配置无效时使用默认值。

> **重要：** 源码中的符号目录比输出目录新时，构建会覆盖输出目录里的副本。`settings.jsonc` 和 `theme.json` 位于构建输出目录，执行 `dotnet clean`、删除 `bin` 或清理发布目录会一并删除。请定期备份修改过的符号目录和快捷键设置；日常使用时，建议发布到一个独立文件夹，而不是长期依赖 `bin/Debug`。

## 符号目录与字母路径 JSONC 格式

配置文件使用 UTF-8 编码，接受 `//` 注释和尾随逗号。格式错误的 JSON 会被拒绝。

顶层结构：

```jsonc
{
  "schemaVersion": 1,

  "positions": [
    { "id": "above", "displayName": "上方" },
    { "id": "below", "displayName": "下方" },
    { "id": "overlay", "displayName": "叠加" }
  ],

  "marks": [
    {
      "id": "acute",
      "codePoint": "U+0301",
      "name": "锐音符",
      "position": "above",
      "description": "可选说明"
    }
  ],

  "composition": {
    "mode": "nfc",
    "rules": []
  },

  // 可选：字母变形路径与其他字符，详见下文。
  "letterComposition": {}
}
```

字段说明：

- `schemaVersion`：当前只支持 `1`。
- `positions`：位置分组，数组顺序就是完整编辑器的分组显示顺序。`id` 只能包含 ASCII 字母、数字、`-`、`_`、`.`，且不能重复。
  - 紧凑窗口用位置 id 决定符号在预览字母四边的位置：`above` / `top` 显示在上方，`below` / `bottom` / `under` 显示在下方，`left` / `right` 显示在左右；其他 id（包括默认的 `overlay`）按数量均衡分配到左右两侧。这个映射只影响紧凑窗口，完整编辑器仍按 `positions` 数组顺序显示。
- `marks`：组合附加符号。`codePoint` 推荐使用 `U+XXXX` 形式；符号必须是 Unicode 组合附加符号（nonspacing、spacing combining 或 enclosing mark）。`position` 必须引用已定义的位置。`id` 和码点都不能重复。
- `composition.mode`：
  - `"nfc"`：默认。输出 NFC 规范化结果。若无法完整预组合，可能得到“部分预组合”的序列。例如 `a` + 锐音符 + 下点符可能得到 `ạ` 加上一个锐音符。
  - `"nfd"`：完全分解输出，永远不使用预组合字符，只输出基础字母与按 NFD 规范排列的组合符号。例如 `a` + 锐音符 + 下点符得到 `U+0061 U+0323 U+0301`。此模式不应用符号例外规则；字母变形路径仍会先生成结果字母。
- `composition.rules`：显式例外映射，只在 NFC 模式下生效。某些字符（例如 `ø`、`ł`、`đ`）没有 NFC 规范分解，不能仅靠基础字母加组合符号自动得到，需要在这里写规则。

一条例外规则：

```jsonc
{
  "base": "o",
  "marks": ["overlay-long-slash"],
  "resultCodePoint": "U+00F8",
  "note": "o + 长斜线 → ø"
}
```

规则行为：

- `base` 必须是单个 Unicode 字母。
- `marks` 必须引用 `marks` 中已定义的符号 id，不能重复。
- `resultCodePoint` 必须是单个 Unicode 字母。
- 规则匹配只看“基础字母和符号 id 的集合”，与符号选择顺序无关。
- 在 NFC 模式下，只要匹配到规则，规则优先于自动组合。
- NFD 模式完全分解，不应用符号例外规则；`letterComposition.rules` 中的变形路径不受影响。
- 同一基础字母和同一组符号 id 不能定义两条重复规则。

### 字母变形与其他字符（letterComposition）

可选的顶级字段 `letterComposition` 用来定义抽象变形操作、字母路径和“其他字符”列表。结构示例：

```jsonc
"letterComposition": {
  "blocks": [
    {
      "id": "latin-1-supplement",
      "displayName": "Latin-1 增补",
      "firstCodePoint": "U+0080",
      "lastCodePoint": "U+00FF"
    }
  ],

  "operations": [
    { "id": "turn", "name": "倒转", "group": "方向", "description": "旋转 180°" },
    {
      "id": "ligature",
      "name": "合字",
      "group": "结构",
      "description": "把两个字母合成一个字符",
      "requiresSecondLetter": true
    }
  ],

  "rules": [
    { "base": "M", "operations": ["turn"], "resultCodePoint": "U+019C", "note": "M + 倒转 → Ɯ" },
    { "base": "i", "second": "j", "operations": ["ligature"], "resultCodePoint": "U+0133", "note": "i + j + 合字 → ĳ" }
  ],

  "otherLetters": [
    {
      "codePoint": "U+00FE",
      "name": "LATIN SMALL LETTER THORN",
      "block": "latin-1-supplement",
      "aliases": ["thorn"]
    }
  ]
}
```

字段说明：

- `blocks`：给“其他字符”分区和搜索用的 Unicode 区块。`firstCodePoint` / `lastCodePoint` 是闭区间，区块范围不能重叠。
- `operations`：抽象变形操作。操作本身没有码点，只作为路径的一部分显示。
  - `group`：操作按钮的分组，缺省为“其他”。
  - `description`：可选说明，显示在悬停提示中。
  - `requiresSecondLetter`：为 `true` 时，使用该操作的规则必须提供第二个字母，界面会显示第二字母输入框。
- `rules`：路径规则，`marks` 与 `operations` 二选一。
  - `operations`：抽象变形路径。按“基础字母 + 操作集合（+ 可选第二个字母）”精确匹配，与操作选择顺序无关，区分大小写。例如 `M + 倒转 → Ɯ`、`i + j + 合字 → ĳ`。这类路径在 NFC 和 NFD 下都会生效。
  - `marks`：组合符号例外映射，写法与 `composition.rules` 相同，只在 NFC 下生效。
  - `second`：仅用于需要第二字母的变形路径；`marks` 形式不能指定。
  - `resultCodePoint`：必须是单个 Unicode 字母。
  - 同一基础字母、同一组操作/符号和同一第二个字母不能重复定义。找不到匹配规则时，界面提示“没有这条组合路径”，不会猜测结果。
- `otherLetters`：没有通用变形路径、需要直接选择的字符。
  - `codePoint` 必须是字母，`name` 用于显示和搜索。
  - `block` 可选，必须引用 `blocks` 中定义的 id；不填时归入“未分组”。
  - `aliases` 可选，用于补充搜索关键词（例如 `thorn`）。
  - 已有路径结果的字符不应放进 `otherLetters`，否则配置校验会报告重复。

如果 `letterComposition` 存在但内容有误（例如引用了不存在的操作、规则重复、结果不是字母），整份符号目录会被拒绝，原因显示在“诊断详情”中；程序只保留这一份符号目录，不会回退到其他文件。

## 全局快捷键设置

设置文件 `Data/settings.jsonc` 在第一次启动时自动创建，默认内容：

```jsonc
{
  "schemaVersion": 1,

  // 全局快捷键：至少一个修饰键 + 一个主键。
  // 支持 Ctrl / Alt / Shift / Win，以及字母、数字、Space、F1-F24（F12 除外）。
  // 修改后重启 Accent It 生效。
  "hotkey": "Ctrl+Alt+Space"
}
```

- `schemaVersion`：当前只支持 `1`。
- `hotkey`：至少包含一个修饰键（Ctrl、Alt、Shift、Win），加一个主键。
- 支持字母 A–Z、数字 0–9、Space、F1–F24。F12 保留给系统调试，配置时会被拒绝。
- 修饰键和主键不区分大小写，例如 `ctrl + shift + a` 会规范化为 `Ctrl+Shift+A`。
- 建议避开常用软件占用的组合，例如 QQ 的 `Ctrl+Alt+A`、微信的 `Alt+A`。
- 修改后重启程序生效；当前不监听设置文件变化。
- 如果组合已被其他程序占用，程序启动时注册失败，主界面会显示冲突提示；其他功能仍可使用，改好设置后重启即可。程序不会自动重新注册。
- 如果设置文件 JSON 格式错误、`schemaVersion` 不支持或快捷键无效，程序使用默认 `Ctrl+Alt+Space`，并在“诊断详情 → 设置问题”中说明原因，不会覆盖原文件。
- 主界面的“打开设置文件”按钮可以直接打开这个文件。
- Win 组合键能否注册取决于系统和已运行程序，可能被系统保留。

## 注意事项与已知限制

### 组合与输出

- 预组合依赖 Unicode NFC 的规范组合规则。像 `ø`、`ł`、`đ` 这类没有规范分解的字母，不能仅靠“基础字母 + 组合符号”自动得到；需要显式规则。
- 字母变形路径必须显式配置，组合器不会根据字形自动推断结果。未配置的“字母 + 操作”组合会提示“没有这条组合路径”。
- “其他字符”列表只包含配置中列出的字符，不是完整的 Unicode 字符选择器；需要更多字符时请在 `letterComposition.otherLetters` 中添加。
- 在 NFD 模式下，变形路径会先生成结果字母，再分解附加符号；符号例外映射不生效。
- 多个组合附加符号的显示效果取决于字体；码点正确不代表所有程序中外观一致。
- Windows 剪贴板和其他应用的文本处理行为可能改变最终的码点表现。

### 跨应用插入

- 自动插入目前只在 Windows 11 记事本和隔离的 Edge 临时页面中实测通过。VS Code、Chrome、Windows Terminal、管理员权限目标等没有实测，不能视为兼容。
- 如果目标应用以管理员权限运行，而 Accent It 不是管理员，Windows 的 UIPI 会阻止 `SendInput`，插入会失败；界面会提示可手动复制。
- 自动插入依赖目标应用接受 Ctrl+V。某些程序可能拒绝粘贴、使用不同的快捷键，或者把粘贴处理成富文本；Accent It 无法确认目标文本是否真的改变，只报告已经尝试发送粘贴。
- 密码框的识别依赖 UI Automation 或经典 Win32 Edit 样式。无法识别为密码框的自绘控件仍可能被当成普通目标；不要在敏感输入框中自动插入。
- 粘贴前会核对顶层窗口、进程/线程和目标焦点是否还能恢复，但无法在所有应用里证明用户意图中的具体光标位置没有变化。焦点无法恢复时会停止自动插入。
- 光标定位依赖目标应用暴露系统光标或 UI Automation；不暴露时回退到鼠标位置或显示器工作区中央。混合 DPI 多显示器、屏幕旋转和特殊窗口布局没有验证。
- 剪贴板备份只覆盖常见格式（UnicodeText、Text、Html、Rtf、Csv、FileDrop、Bitmap），延迟渲染或特殊格式不能保证完整恢复。剪贴板历史可能记录临时插入结果。
- 插入后 Windows 可能拒绝把紧凑窗口自动切回前台；此时窗口仍置顶，可点击按钮关闭，或再按一次全局快捷键把它带回前台。
- 输入法正在组合输入时按 Enter 的行为尚未专门测试；组合符号的显示效果取决于字体。
- 目标关闭、目标最小化、焦点无法恢复、剪贴板失败或发送失败时会停止自动插入，保留结果供手动复制。

### 界面与运行

- 全局快捷键只在启动时注册一次。启动时若被占用，即使占用的程序之后退出，Accent It 也不会自动重新注册，需要重启。
- 系统托盘使用 Windows 自带的 WinForms `NotifyIcon`，图标是系统默认应用图标，没有专门制作图标。Windows 11 默认把新图标放进“显示隐藏的图标”溢出区，可能不在任务栏常驻区域。
- 紧凑窗口固定为 460×430 DIP，不能调整大小；符号很多时四边区域会换行，内容过高时出现滚动条。符号名称只在悬停提示和辅助功能名称中显示。
- 界面主题只能手动切换，不跟随 Windows 系统主题，也没有键盘快捷键。主题选择写入 `Data/theme.json`；文件不可写时本次切换仍然生效，但下次启动会回到浅色。
- 标题栏配色依赖 DWM 的沉浸式深色模式和自定义标题栏颜色。Windows 10 或更早版本可能只显示系统深色标题栏，界面配色仍正常；已在 Windows 11 上验证，未覆盖其他版本。
- 当前不包含开机启动和安装包。

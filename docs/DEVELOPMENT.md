# Accent It 开发记录

本文记录项目目标、当前进度、关键实现和开发命令。用户使用说明见 [README](../README.md)，实际运行测试记录见 [TESTING](TESTING.md)。

## 项目目标

- 保留一个独立可用的 Unicode 组合编辑器：输入基础字母、选择组合符号或抽象变形操作、预览并复制结果。
- 用全局快捷键把组合能力带到其他 Windows 应用：捕获目标窗口和光标，打开紧凑输入窗口，尝试粘贴结果。
- 符号目录、位置分组、例外规则、字母变形路径、其他字符和全局快捷键都由用户可编辑的 JSONC 文件控制，不写死在代码里。
- 特殊字母通过“字母 + 操作”的显式路径组成，而不是变成一个 Unicode 字符选择器；没有通用路径的字符才进入“其他字符”列表。
- 只使用 Windows 自带能力和 .NET/WPF 框架，不引入第三方 UI、热键或数据库依赖。
- 对焦点、剪贴板和跨应用插入明确报告限制，不把“已发送粘贴”说成“目标一定已修改”。

## 技术栈

- C#、.NET 10、WPF（`net10.0-windows`）
- xUnit
- JSONC 配置；System.Text.Json 负责解析
- Win32 P/Invoke、UI Automation、WinForms `NotifyIcon`（仅用于托盘）

## 当前进度

### 阶段 1：完整编辑器 MVP（已完成）

- 输入单个基础字母，按位置分组显示组合符号。
- 鼠标点击或 Tab + 空格选择符号；实时预览，可单独移除、撤销或清空。
- 默认 NFC 预组合，可切换 NFD 完全分解。
- 显示组合方式、Unicode 码点、NFC/NFD 诊断信息，支持复制结果。
- 从 JSONC 读取符号目录、位置分组、组合策略和例外规则；无效配置会报告问题并拒绝加载，不覆盖文件。
- 符号目录直接读取 `Data/accents.default.jsonc`，不生成用户副本；旧版 `accents.jsonc` 保留在原处但不再参与加载。

### 阶段 2：全局输入工作流（已完成）

1. **全局快捷键**：从 `Data/settings.jsonc` 读取快捷键（默认 `Ctrl+Alt+Space`），用 `RegisterHotKey` 注册；注册失败不崩溃。快捷键只在启动时注册一次。
2. **紧凑输入窗口**：约 460×430 DIP，置顶、不显示在任务栏；复用同一份符号目录和组合逻辑，支持基础字母、实时预览和 NFC/NFD。
3. **目标定位与跨应用插入**：捕获前台窗口、进程/线程、输入焦点和光标位置，按物理像素放置窗口；确认时备份剪贴板、恢复目标焦点、发送 Ctrl+V，关闭时尽量恢复原剪贴板。
4. **后台运行与托盘**：关闭完整编辑器改为隐藏到托盘；托盘菜单可重新打开或退出，退出时释放托盘图标并注销全局快捷键。
5. **紧凑布局与窗口切换**：符号按位置围绕预览字母排列；主窗口和紧凑窗口用按钮或 F2 互相切换，并保留当前输入。
6. **深夜模式**：主窗口和紧凑窗口共用主题选择；冷调蓝黑配色覆盖内容区和 Windows 11 标题栏；主题写入单独的 `Data/theme.json`。
7. **界面精简**：移除不影响操作的说明文字，缩短插入后的状态提示；紧凑窗口字体和基础字母输入框放大，状态详情保留在悬停提示中。

### 阶段 3：字母变形与其他字符（已完成）

- 在 `accents.default.jsonc` 中新增可选的 `letterComposition` 段，包含 `blocks`、`operations`、`rules` 和 `otherLetters`。
- 抽象变形操作（倒转、反向、加钩、合字等）只作为路径的一部分；路径按“基础字母 + 精确操作集合（+ 第二字母）”匹配，顺序无关，找不到时提示“没有这条组合路径”。
- 覆盖 Latin-1 增补、拉丁扩展 A/B 和国际音标扩展四个区块；没有通用变形关系的字符进入可搜索的“其他字符”列表。
- 完整编辑器增加“组合符号 / 字母变形 / 其他字符”三个标签页、第二字母输入和路径状态。
- 紧凑窗口增加“变形”“其他”覆盖面板、操作开关、第二字母输入、路径/错误反馈；Backspace 依次删除第二字母、最后一个变形、最后一个符号。
- 符号目录只保留 `Data/accents.default.jsonc` 一份；旧版 `accents.jsonc` 不再读取，避免两份配置不一致。
- 变形路径在 NFC 和 NFD 下都生效；符号例外映射仍只在 NFC 下生效。

## 关键实现

### 设置与全局快捷键

- 设置文件缺失时创建，存在时只读取，不覆盖；格式错误、版本不支持或快捷键无效时回退到默认值，并记录到诊断信息。
- 使用 `RegisterHotKey` + 专用 message-only `HwndSource` 接收 `WM_HOTKEY`，附带 `MOD_NOREPEAT`；不使用全局键盘钩子。
- 热键触发时先捕获目标，再显示或激活紧凑窗口；重复触发不会重建窗口或清空输入。

### 紧凑窗口

- 主窗口和紧凑窗口共享组合快照；从主窗口切换时保留输入，从外部目标按快捷键打开时从新的组合状态开始。
- 符号按位置 id 映射到预览字母四边：上方、下方各一排，左右分列；未知位置按数量分配到左右。
- 符号按钮只显示符号本身，名称和码点放在悬停提示与辅助功能名称中。
- 插入成功后清空输入以便连续输入，但窗口保持打开；关闭窗口不会撤销已经插入的文本。

### 字母变形与其他字符

- `LetterCompositionCatalog` 保存区块、操作、路径规则和其他字符；加载时校验 id、引用、码点、重复路径和区块重叠。
- 路径匹配对操作集合和符号集合都使用集合比较，忽略选择顺序，不做大小写或字形推断；未命中时统一返回“没有这条组合路径”。
- 操作路径先得到结果字母，再叠加组合符号：NFC 下继续尝试符号例外/路径，NFD 下只做分解。这样 `M + 倒转` 在两种模式下都能得到 `Ɯ`。
- 符号目录只保留一份：加载器直接解析 `accents.default.jsonc`；任何校验错误都会拒绝整份目录并显示位置，不再做旧配置内存补充。
- 完整编辑器与紧凑窗口复用同一组合逻辑和配置，路径文案保持一致，避免两个界面给出不同答案。

### 目标捕获与插入

- 用 `GetForegroundWindow`、`GetWindowThreadProcessId` 和 `GetGUIThreadInfo` 捕获目标；首选 Win32 系统光标，失败时用 UI Automation 文本选区/输入框边界，再退回鼠标位置或目标显示器工作区中央。
- 位置按物理像素计算，用 `SetWindowPos` 放置，避免 DPI 换算偏移。
- 插入前重新验证目标存在、进程/线程一致和焦点可恢复；备份常见剪贴板格式，写入结果，等待修饰键释放，核对剪贴板后再发送 Ctrl+V。
- 密码框不读取内容，不执行自动插入；目标关闭、焦点无法恢复或剪贴板失败时停止插入，保留结果供手动复制。
- 关闭紧凑窗口时，只有剪贴板仍是本次结果才恢复备份；用户点过“复制结果”或期间复制了新内容时不覆盖。

### 主题与托盘

- 主题通过替换应用级 `ResourceDictionary` 实现，浅色和深夜主题共用同一组资源键。
- Windows 11 标题栏使用 DWM 沉浸式深色模式（属性 20/19）和自定义标题栏颜色（属性 35）；不支持时内容区主题仍正常。
- 托盘使用 WinForms `NotifyIcon` 和系统默认应用图标；托盘图标创建失败时退回“关闭主窗口即退出”。

## 构建与测试

在仓库根目录执行：

```bash
dotnet build AccentIt.slnx
dotnet test AccentIt.slnx
dotnet run --project src/AccentIt
```

项目使用 .NET 10 的 `.slnx` 解决方案格式，使用 `dotnet` CLI 即可，不依赖 Visual Studio。

当前有 99 个自动化测试，覆盖：

- JSONC 配置解析、校验、默认目录加载与缺失/无效处理
- 快捷键解析、设置文件创建与回退
- NFC/NFD 组合、部分预组合、例外规则、Unicode 非 BMP 字符
- 字母变形路径、第二字母合字、无路径提示、路径在 NFC/NFD 下的行为
- `letterComposition` 校验、默认目录路径/其他字符覆盖
- 紧凑窗口定位、四边符号分组
- 主题选择读写

界面和跨应用行为使用系统临时目录中的 PowerShell UI Automation 脚本验证；脚本和截图放在系统临时目录，不进入仓库。详细结果见 [TESTING](TESTING.md)。

## 暂不包含

- 安装包、开机启动、自动更新
- 跟随 Windows 系统主题自动切换
- 快捷键占用解除后的自动重新注册
- 全局键盘钩子、输入法注入、OCR、跨设备同步
- 对所有 Windows 应用、管理员权限目标或所有输入法的兼容保证
